## 2. 教師あり学習:価格予測

### 何を予測するか
- 目的変数:`log1p(price_usd)`(価格 USD に 1 を足して対数を取ったもの)。対数にする理由は、上の分布が右に長いため。
- 入力は出品フォームにある 4 項目だけ:商品名・カテゴリ(トップ)・ブランド・状態。

### 特徴量(保存された `price.joblib` を読み込んで確認)

| 入力 | 変換 | 列数 |
|---|---|---|
| 商品名 | TF-IDF(単語の 1〜2 連続、3 商品以上に出る語、上限 100,000 語、sublinear_tf) | 100,000 |
| カテゴリ(トップ) | one-hot | 17 |
| ブランド(前後の空白を取り小文字化) | one-hot(train で 20 回未満のブランドは 1 つにまとめる) | 3,431 |
| 状態 | one-hot | 5 |
| 合計 | | 103,453 |

### モデル
- **Ridge 回帰、alpha = 3.0**(solver = sparse_cg、乱数の種 42)。記録上の名前は `ridge[top] alpha=3.0`。
- 保存ファイル `price.joblib` は 2.16 MB。学習スクリプト全体の実行時間は 157.9 秒。
- 環境:Python 3.13.14、scikit-learn 1.9.1、numpy 2.5.4、pandas 3.1.1。使った機械(CPU・メモリ)は不明(リポジトリに記録なし)。

### モデルの選び方(validation だけで決めた)

| 候補(validation) | MAE USD | 中央絶対誤差 USD | R²(対数) | R²(USD) | RMSE(対数) |
|---|---|---|---|---|---|
| ridge[top] alpha=0.3 | 33.77 | 10.53 | 0.500 | 0.318 | 0.7351 |
| ridge[top] alpha=1.0 | 33.58 | 10.47 | 0.507 | 0.315 | 0.7300 |
| ridge[top] alpha=3.0 | 33.73 | 10.44 | 0.508 | 0.299 | 0.7297 |
| ridge[top/sub] alpha=0.3 | 33.50 | 10.45 | 0.508 | 0.327 | 0.7294 |
| ridge[top/sub] alpha=1.0 | 33.31 | 10.38 | 0.515 | 0.325 | 0.7243 |
| ridge[top/sub] alpha=3.0 | 33.44 | 10.34 | 0.516 | 0.309 | 0.7237 |
| hist_gradient_boosting[top] | 37.21 | 11.92 | 0.378 | 0.187 | 0.8202 |

- 規則(コードに先に書いてある):カテゴリの持ち方ごとに、validation の RMSE(対数)が最小のものを選ぶ。サブカテゴリまで使う版(top/sub)は、validation の MAE が 3% 以上良くなるときだけ採用。
- 結果:top/sub にしたときの MAE の改善は 0.86% で 3% に届かず、トップカテゴリだけの `ridge[top] alpha=3.0` を採用。
- 正直な注記:
  - alpha は 0.3 / 1.0 / 3.0 の 3 つしか試していない。選ばれた 3.0 は試した範囲の端なので、もっと大きい alpha のほうが良い可能性は確かめていない。
  - 3 つの alpha の差は小さい(RMSE 対数で 0.7297〜0.7351)。MAE(USD)だけを見ると alpha=1.0(33.58)のほうが 3.0(33.73)より少し良い。
  - HistGradientBoosting は設定を 1 通り(SVD 50 次元、max_iter 300、learning_rate 0.1)しか試していない。「木のモデルは Ridge より悪い」とまでは言えず、「この設定では悪かった」まで。

### test の成績(最後に 1 回だけ使った。141,614 商品)

| | MAE USD | 中央絶対誤差 USD | R²(対数) | R²(USD) | RMSE(対数) |
|---|---|---|---|---|---|
| **Ridge(採用モデル)** | 34.13 | 10.50 | 0.510 | 0.279 | 0.7300 |
| ベースライン:カテゴリ別の中央値 | 45.30 | 14.00 | 0.012 | -0.057 | 1.0362 |
| ベースライン:全体の中央値 | 45.63 | 14.03 | -0.026 | -0.067 | 1.0561 |
| ベースライン:カテゴリ+サブカテゴリ別の中央値 | 43.67 | 13.00 | 0.129 | -0.016 | 0.9728 |

- MAE は 34.13 USD。カテゴリ別中央値のベースライン(45.30 USD)より 24.7% 小さい。
- R²(対数)は 0.510。対数価格のばらつきの約半分を説明できている、という水準。残り半分は説明できていない。
- R²(USD、対数を戻した実額)は 0.279 で、対数のときよりかなり低い(→ 4 章「高い商品」)。
- 1 USD = 150 円の固定で換算すると、MAE は約 5,119 円、中央絶対誤差は約 1,575 円(アプリの `model.mae` はこの換算値)。

**同じ商品名が train に無い商品だけでの成績**(重複出品で成績が甘くなっていないかの確認。test のうち 116,197 商品 = 82.1%)

| | MAE USD | R²(対数) |
|---|---|---|
| Ridge | 34.73 | 0.489 |
| カテゴリ別の中央値 | 45.18 | 0.009 |

少し下がる(R² 0.510 → 0.489)が、ベースラインとの差は保たれている。

### 予測の幅(low 〜 high)の出し方
- 方法:validation での残差(実際 − 予測、対数空間)の 25% 点と 75% 点を、予測値に足す(`validation residual quantiles in log1p space, added to the prediction`)。
- 値:25% 点 -0.4498、75% 点 0.3949。(価格+1)に対して約 ×0.64 〜 ×1.48 の幅にあたる。
- **test で実際の価格がこの幅に入った割合:50.3%**(ねらいは 50%)。10% 点〜90% 点の幅なら 80.1%(ねらいは 80%。アプリではこちらは使っていない)。
- 読み方の注意:
  - 画面の「low 〜 high」は、**実際の価格の約半分が外れる幅**。「この中に必ず入る」という意味ではない。
  - 幅は全商品で同じ(対数で一定)。カテゴリや価格帯ごとに幅を変えていないので、ばらつきの大きい種類の商品では実際より狭く出ている可能性がある。カテゴリ別・価格帯別に入った割合は不明(リポジトリに記録なし)。

## 3. 教師なし学習:クラスタリング

### パイプライン(保存された `cluster.joblib` を読み込んで確認)
1. 入力の文字列 =「商品名 + トップカテゴリ名」
2. TF-IDF(英語のストップワードを除く、5 商品以上に出る語、上限 20,000 語 → 実際の語彙 20,000 語)
3. TruncatedSVD で 50 次元に圧縮(説明できた分散は 14.8%)
4. L2 正規化
5. KMeans(**k = 38**、n_init = 5、乱数の種 42)

- TF-IDF と SVD は全 1,416,142 商品で学習。KMeans は固定の 300,000 件のサンプルで学習し、全商品に割り当てた。
- 保存ファイル `cluster.joblib` は 4.33 MB。実行時間 163.7 秒。保存したパイプラインを読み直して 5,000 件を割り当て直した一致率は 100%。

### シルエット係数
- **0.356**(euclidean on L2-normalized SVD vectors, fixed random sample of 20000 items)。全商品ではなく、固定の 20,000 件のサンプルで測った値。
- -1〜1 の指標で、1 に近いほどクラスタがはっきり分かれている。0.356 は「はっきり分かれている」とは言えない水準。

### k の決め方と、その根拠が弱いこと
- 規則(`smallest candidate k (8..40) with silhouette >= max - 0.01`):k = 8, 10, …, 40 のうち、シルエット係数が「最大値 − 0.01」以上になる最小の k。

**根拠が弱い理由(表から読めること)**
1. **シルエット係数は k を増やすほどほぼ上がり続けていて、山(ここが最適という点)が無い。** 候補の最大は範囲の上端の k=40。参考に測った k=50〜100 でも 0.373〜0.386 と、さらに高い。
2. つまり **k=38 は「データが 38 個に分かれているから」ではなく、「候補の上限を 40 にしたから」決まった数**。上限 40 の理由は、画面で人が見分けるラベルの数として決めたもの(`ml/train_cluster.py` のコメント)で、データから出た数ではない。
3. 慣性の減り方にも、はっきりした折れ曲がり(肘)は無い(k を 2 増やすごとに 1〜7% ずつ減り続ける)。
4. 許容幅 0.01 も人が決めた値。探索時(n_init=3)の k=38 は 0.3609、最終モデル(n_init=5)は 0.3556 で、初期値の違いだけで約 0.005 動く。0.01 の差に強い意味は持たせられない。
5. 乱数の種は 1 つ(42)だけ。種を変えたときにクラスタがどれだけ入れ替わるかは不明(リポジトリに記録なし)。

言えること:「k は 40 以下という画面の都合の中で、シルエット係数がほぼ最大になる数を選んだ」。言えないこと:「38 が最適なクラスタ数である」。

## 4. 限界

1. **米国のデータを、固定の 1 USD = 150 円で円にしているだけ。** 学習したのは Mercari US の USD の価格。円の値は `app/ml/predictor.py` の `USD_JPY = 150` を掛けて 100 円単位に丸めたもので、実際の為替でも日本の相場でもない。日本での人気・送料・流通量の違いは入っていない。
2. **語彙は英語だけ。** 商品名の特徴量は英語の出品タイトルから作った単語。日本語だけの商品名は学習済みの語に 1 つも当たらず、価格はカテゴリ・ブランド・状態だけで決まり、クラスタは割り当てられない。アプリでは Gemini で英語に直してからモデルに渡している(`app/services/ai.py` の `title_for_ml`)が、その英訳を通したときの精度は測っていない(不明、リポジトリに記録なし)。ブランドとカテゴリも、学習データにあった英語の名前しか知らない。
3. **高い商品で誤差が大きい。** 記録から言える根拠は 3 つ。
   - MAE(34.13 USD)が中央絶対誤差(10.50 USD)の約 3.3 倍。半分の商品は 10.5 USD 以内で当たるが、少数の大外れが平均を押し上げている。
   - R² が対数では 0.510 なのに、実額(USD)では 0.279 に落ちる。実額では高い商品の誤差が強く効くため。
   - 価格の分布は中央値 24.035 USD に対して 95% 点が 210 USD、最大 5000 USD。高い商品は数が少ない。(推測:対数で学習したモデルは高い商品を低めに見積もりやすい、と一般に言われる。このモデルで偏りの向きを確かめた記録は無い。)
   - ただし、**価格帯別の誤差(例:200 USD 以上の商品での MAE)は記録していない(不明、リポジトリに記録なし)**。「どのくらい大きいか」は数字で言えない。
4. **精度そのものが中くらい。** 対数価格のばらつきの約半分しか説明できていない。MAE 34 USD は、価格の中央値 24 USD より大きい。商品名・カテゴリ・ブランド・状態だけでは、同じ名前で状態や付属品が違う商品を区別できない(画像・説明文は元データに無い)。
5. **期間が 1 か月(2023 年 5 月)だけ。** 季節による変化や、その後の値動きは入っていない。分割もランダムで、「過去で学習して未来を当てる」形の評価はしていない。
6. **予測の幅は約 50% しか入らない**(2 章)。しかも全商品で同じ幅。
7. **k=38 の根拠は弱く、クラスタの一部は寄せ集め**(3 章)。
8. **ライセンスは CC BY-NC 4.0(非営利のみ)。** このデータで学習したモデルは、商用のサービスには使えない(`seed/README.md`)。
9. **再現性。** 乱数の種は 42 で固定。ただし `data/` の元データは Git に入れていない(`.gitignore`)ので、リポジトリだけでは学習をやり直せない。

## 5. 学習のやり直し方
```bash
pip install -r ml/requirements-train.txt   # pandas・pyarrow が要る
# data/ に merrec0.parquet 〜 merrec3.parquet を置く
python -m ml.train_price      # → models_ml/price.joblib, price_metrics.json, price_aux.json
python -m ml.train_cluster    # → models_ml/cluster.joblib, cluster_info.json
```
学習し直すとクラスタ番号の中身が変わるので、`models_ml/cluster_labels_ja.json`(日本語名と hidden)を付け直すこと。付け直すまでは、英語のラベルが一致しない行は自動で無視される。
